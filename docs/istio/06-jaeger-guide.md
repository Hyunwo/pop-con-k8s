# Jaeger 사용 가이드

## Jaeger란?

Jaeger는 분산 트레이싱 도구입니다. 하나의 API 요청이 여러 서비스를 거칠 때 각 서비스에서 얼마나 시간이 걸렸는지, 어디서 에러가 발생했는지를 추적합니다.

Kiali가 서비스 간 트래픽 흐름을 시각화한다면, Jaeger는 **단일 요청의 전체 흐름을 단계별로 추적**하는 용도입니다.

Istio Envoy 사이드카가 자동으로 트레이스를 수집해 Jaeger로 전송하므로 별도 코드 수정이 필요 없습니다.

---

## 언제 사용하나?

| 상황 | 활용법 |
|---|---|
| 특정 요청이 느릴 때 | 어느 서비스에서 병목이 발생하는지 단계별 확인 |
| 에러 원인 파악 | 에러가 발생한 정확한 서비스와 구간 확인 |
| 서비스 간 호출 순서 확인 | A → B → C 순서로 호출이 이루어지는지 추적 |
| 배포 후 응답시간 변화 확인 | 특정 서비스 배포 전후 응답시간 비교 |

---

## 1. 접속

**URL**: `https://jaeger.popcon.store`

---

## 2. 트레이스 검색

1. 상단 **Search** 탭 클릭
2. **Service** 드롭다운에서 조회할 서비스 선택
3. 필요 시 추가 필터 설정:

| 필터 | 설명 |
|---|---|
| **Operation** | 특정 API 엔드포인트로 좁히기 |
| **Tags** | `http.status_code=500` 등 조건 필터 |
| **Lookback** | 조회 시간 범위 (Last 1h, Last 6h 등) |
| **Min Duration** | 특정 시간 이상 걸린 요청만 조회 |
| **Limit Results** | 최대 조회 개수 |

4. **Find Traces** 버튼 클릭

---

## 3. 트레이스 읽는 법

검색 결과에서 트레이스 클릭 시 상세 화면으로 이동합니다.

### 구성 요소

| 용어 | 의미 |
|---|---|
| **Trace** | 하나의 요청 전체 흐름 |
| **Span** | 각 서비스에서 처리된 단위 작업 |
| **Duration** | 전체 요청 처리 시간 |

### 화면 구성

```
[istio-ingressgateway] ────────────────────── 150ms
  [backend-auth] ──────────────── 120ms
    [backend-user] ──────── 80ms
      [rds-mysql] ── 30ms
```

- 가로 막대 길이 = 처리 시간
- 들여쓰기 = 서비스 호출 깊이
- 빨간색 표시 = 에러 발생 구간

### Span 클릭 시 상세 정보

| 항목 | 내용 |
|---|---|
| **HTTP Method/URL** | 어떤 요청인지 |
| **Status Code** | 응답 코드 |
| **Duration** | 해당 서비스 처리 시간 |
| **Tags** | 요청 메타데이터 |
| **Logs** | 해당 시점 로그 |

---

## 4. 에러 트레이스 찾기

1. **Tags** 필터에 `error=true` 입력
2. **Find Traces** 클릭
3. 빨간색으로 표시된 트레이스 클릭
4. 빨간색 Span을 찾아 클릭 → 에러 메시지 확인

---

## 5. 샘플링 정책

현재 프로젝트는 **Rate Limiting 샘플링**을 적용하고 있습니다.

| 상황 | 동작 |
|---|---|
| 평상시 | 대부분의 요청 추적 |
| 트래픽 급증 시 | 초당 최대 100개 Span만 추적 (스토리지 보호) |
| 에러 발생 시 | 트래픽 양과 관계없이 **항상 추적** |

> 에러는 항상 추적되므로 장애 상황에서 누락 없이 확인할 수 있습니다.

---

## 6. Kiali에서 Jaeger 연동

Kiali 그래프에서 노드 클릭 → **Traces** 탭 클릭 시 해당 서비스의 Jaeger 트레이스로 바로 이동할 수 있습니다.
