# PopCon 트러블슈팅 이력

## 1. 좀비 NodeClaim 문제 (Karpenter)

### 현상
- Spot 인스턴스 중단 시 NodeClaim이 삭제되지 않고 좀비 상태로 남음
- 수동 삭제해도 계속 재발

### 원인
- ap-northeast-2c AZ의 t3a.medium, t3.medium Spot 풀 고갈
- Karpenter 로그: "attempted to remove nonexistent offering (t3a.medium, ap-northeast-2c, spot)" 반복

### 해결 과정
1. 수동 삭제 → 재발
2. finalizer 강제 제거 → 임시 해결
3. Karpenter 로그 분석으로 근본 원인 파악
4. NodePool에서 medium 인스턴스 제거 (t3a.large, t3a.xlarge, t3.large, t3.xlarge만 유지)
5. terminationGracePeriod: 10m 추가

### 파일
- gitops/prod/karpenter/nodepool.yaml

## 2. startupProbe 타임아웃 (auction, draw, user 반복)

### 현상
- 새 이미지 배포 시 Pod 재시작 반복 (CrashLoopBackOff)
- startupProbe HTTP 500 오류

### 원인
- Spring Boot 앱 기동 시간 (~180초)이 startupProbe 최대 허용 시간(30 + 15×10 = 180초)과 거의 동일
- 앱이 정상 기동 완료됐지만 이미 SIGTERM 발송된 상태

### 해결
- failureThreshold: 15 → 30 (최대 허용 시간 180초 → 330초)
- auction, draw, user 서비스 모두 동일하게 적용

### 추가 발견 (draw 서비스)
- 새 이미지에서 JPA 쿼리 버그 발견
- DrawEntryRepository.countOngoingByUserId()에서 존재하지 않는 `announcementAt` 필드 참조
- 개발팀 코드 수정 후 재배포로 해결

### 파일
- gitops/prod/backend/auction/deployment.yaml
- gitops/prod/backend/draw/deployment.yaml
- gitops/prod/backend/user/deployment.yaml

## 3. Istio AuthorizationPolicy SA 이름 불일치

### 현상
- AuthorizationPolicy 적용 후 Ingress Gateway → 내부 서비스 통신 전부 차단

### 원인
- AuthorizationPolicy에 설정된 SA 이름: `istio-ingressgateway-service-account`
- 실제 SA 이름: `istio-gateway-prod`

### 해결
- 올바른 SA 이름으로 수정

### 교훈
- 보안 정책 적용 전 단일 서비스에서 먼저 테스트
- Kiali로 차단 구간을 시각적으로 확인

### 파일
- gitops/prod/istio/authorization-policies.yaml

## 4. Envoy 사이드카 OOMKilled (Coraza WASM)

### 현상
- backend-user Pod의 istio-proxy 컨테이너 재시작 반복 (1/2 상태)

### 원인
- Coraza WASM 바이너리 로드 시 최소 150~200Mi 필요
- sidecar.istio.io/proxyMemoryLimit: 128Mi로 부족 → OOMKilled

### 해결
- proxyMemoryLimit: 128Mi → 256Mi 상향

### 파일
- gitops/prod/backend/user/deployment.yaml

## 5. Git 브랜치 충돌

### 현상
- 로컬 브랜치와 원격 브랜치 불일치
- 잘못된 브랜치에서 커밋 후 push rejected

### 해결
- git fetch --prune으로 원격 상태 동기화
- 삭제된 원격 브랜치의 로컬 브랜치 정리
- cherry-pick으로 커밋을 main으로 이동
