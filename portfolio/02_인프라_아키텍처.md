# PopCon 인프라 아키텍처

## 외부 아키텍처 (요청 흐름)
```
사용자 → Cloudflare → ALB → Istio Ingress Gateway → EKS 각 서비스
```

### Cloudflare
- DDoS 방어 (레이어 3/4/7)
- CDN 캐싱 (전 세계 300+ POP)
- DNS 관리
- 무료 플랜 사용

### ALB
- 로드 분산

### Istio Ingress Gateway
- 외부 트래픽 진입 제어
- popcon.store → frontend
- api.popcon.store → 8개 백엔드 서비스

### EKS 클러스터
- 리전: ap-northeast-2
- 가용 영역: ap-northeast-2a, ap-northeast-2c
- 쿠버네티스 버전: 1.35

## 내부 아키텍처

### 컴퓨팅
- EKS Worker Node: t3a.large, t3a.xlarge, t3.large, t3.xlarge
- Karpenter NodePool: t1-prod-eks
- capacity-type: spot + on-demand
- terminationGracePeriod: 10m

### 데이터 계층
- RDS MySQL: 영구 저장 (Multi-AZ)
- RDS Proxy: 연결 풀링 (Pod 수 증가에 따른 연결 폭발 방지)
- Redis (ElastiCache): 캐시 + 실시간 상태 처리 + 대기열
- 모두 Private Subnet 배치

### 시크릿 관리
- AWS Parameter Store: 민감 정보 중앙 관리
- External Secrets Operator: K8s Secret으로 자동 주입
- IRSA (IAM Roles for Service Accounts): 서비스별 AWS 권한 관리

### 자동 확장
- Karpenter: 노드 자동 프로비저닝 (Pending Pod 감지 → 즉시 노드 생성)
- HPA: CPU 기준 Pod 수평 확장 (목표 60%)
- Consolidation: WhenEmptyOrUnderutilized, 5분 유휴 후 통합

### 모니터링
- Prometheus + Grafana: 메트릭 수집 및 대시보드
- Jaeger: 분산 트레이싱
- Kiali: 서비스 메시 시각화
- Envoy 사이드카에서 자동 수집 (코드 수정 불필요)

## CI/CD
- GitHub Actions: CI (빌드, 테스트, ECR 푸시)
- ArgoCD: CD (GitOps 방식, gitops 레포 → EKS 자동 반영)
- ECR: 컨테이너 이미지 저장소

## Terraform
- S3 backend로 state 관리
- modules: eks, rds, redis, karpenter, iam 등
- global/iam: IAM 리소스 관리
