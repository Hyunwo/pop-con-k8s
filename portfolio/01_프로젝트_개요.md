# 01. 프로젝트 개요

## 프로젝트명
**PopCon** (팝업스토어 티켓팅 서비스)

## 프로젝트 목적
팝업스토어 이벤트 오픈 순간, 짧은 시간에 수만 명이 동시 접속하는 상황에서
서비스가 안정적으로 동작하도록 클라우드 인프라를 설계하고 구축.

## 핵심 문제 정의
1. **트래픽 집중 문제**: 평소엔 한산하다가 이벤트 오픈 순간에만 폭발적으로 몰림
2. **정합성 문제**: 동시에 수천 명이 입찰/응모할 때 초과 판매가 나면 안 됨
3. **보안 문제**: 매크로 자동 응모 차단, 내부 서비스 간 통신 보호

| 항목 | 목표 |
|---|---|
| 목표 동시 접속자 (CCU) | 22,500명 (15,000석 × 1.5배 여유 계수) |

## 마이크로서비스 구성 (8개)
| 서비스 | 역할 | 특이사항 |
|---|---|---|
| backend-user | 사용자 관리 | S3 IRSA 적용 (프로필 이미지) |
| backend-auth | 인증/인가 | |
| backend-popup | 팝업스토어 정보 | |
| backend-auction | 경매 서비스 | 정합성 최중요, Circuit Breaker 3회 |
| backend-draw | 드로우(추첨) 서비스 | 정합성 중요, Circuit Breaker 3회 |
| backend-queue | 대기열 진입/폴링 | 트래픽 집중 최고점 |
| backend-queue-worker | 대기열 메시지 소비 | HTTP 엔드포인트 없음, 큐만 소비 |
| backend-anti-macro | 매크로 탐지 | |
| frontend | React 프론트엔드 | |

## 특이사항
- ticket-service: Ingress 라우팅 제외, X-Internal-Secret 헤더 검증으로 내부 호출만 허용
- 모든 서비스: Spring Boot 3.5.5, Java 21, 프로파일 "staging" 사용
- 모든 서비스: 2개 Pod, 2개 AZ 분산 배치 (topologySpreadConstraints)

## 네임스페이스
- popcon-prod: 서비스 운영
- istio-system: Istio 컴포넌트 (Ingress Gateway 포함)
- karpenter: Karpenter 컴포넌트
- argocd: ArgoCD
- monitoring: Prometheus, Grafana
